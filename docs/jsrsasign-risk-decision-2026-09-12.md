## Exact Reachability And Evidence

- The sole production path is `capitol-ledger@0.1.0 -> @apple/app-store-server-library@3.1.0 -> jsrsasign@11.1.5`. The application does not import `jsrsasign` directly. Relevant runtime siblings on Apple's path are `jsonwebtoken@9.0.3` and `node-fetch@2.7.0`.
- Apple's package declares `jsrsasign: ^11.0.0`; CapitolWonk's frozen pnpm 9 lock resolves exactly one `11.1.5` path. Locked integrities are Apple `sha512-d26SICRz8BwCV2qPR0BSXBMxmw0NEvJLwsdREcBmCrus8NmyHw2XgOOP0fiFjcctPn/JXtmSDuGVnaHe+dqO+A==` and `jsrsasign` `sha512-i6mAjey0/4UQmlOaNS2vROl8EkWV8Ei436reJAby2OPQ3lF6uXSs1VYpnM8hndmmCMFIzNc04Uw2GF+0JVLFbg==`.
- `@apple/app-store-server-library@3.1.0` is the latest published Apple release as of this review. Merged, unreleased [PR #437](https://github.com/apple/app-store-server-library-node/pull/437) raises the dependency floor to `^11.1.5` and fixes `ReceiptUtility`; it is integration provenance, not a `SignedDataVerifier`/#447 fix. Published `3.1.0`'s caret range already permits CapitolWonk's locked `11.1.5`.
- `jsrsasign` declared [end of support effective August 14, 2026](https://github.com/kjur/jsrsasign#end-of-support). Fresh frozen production and full audits reported no advisory affecting the resolved graph. No known advisory is not evidence of active maintenance or correctness.
- CapitolWonk creates Apple's verifier with online checks enabled in `lib/billing/app-store-server.ts`. `jsrsasign` is reachable through X.509 and OCSP ASN.1 parsing/request construction; other libraries perform the principal JWS and cryptographic signature checks.
- Apple's open [issue #447](https://github.com/apple/app-store-server-library-node/issues/447), filed September 5, documents a date-format mismatch: `jsrsasign` emits GeneralizedTime ending in `Z`, while Apple's parser expects only fourteen digits. The resulting invalid date makes stale/future comparisons fail to reject. A replayed, previously signed `good` OCSP response can therefore evade the intended freshness check.
- An arbitrary caller can reach public JWS/X.509 parsing, which creates a separate parser/resource-exhaustion surface. The #447 integrity scenario has stricter prerequisites: chain trust is checked, the AIA URL comes from the trusted chain, and the OCSP response must be signed/authorized and match the certificate identifier. Exploitation therefore requires causing the verifier to receive or replay an old correctly signed matching `good` response through network, cache, or responder influence. The issue does **not** bypass the OCSP signature, responder authorization, certificate-chain validation, or JWS signature, and it does not demonstrate arbitrary entitlement forgery.
- Open [PR #451](https://github.com/apple/app-store-server-library-node/pull/451) proposes strict UTC parsing and signed OCSP regression tests. It was not merged or released at this review.
- Adjacent watch items are [issue #455](https://github.com/apple/app-store-server-library-node/issues/455) and [PR #456](https://github.com/apple/app-store-server-library-node/pull/456) for an OCSP timeout that does not abort the underlying request, plus [issue #450](https://github.com/apple/app-store-server-library-node/issues/450) for incomplete nested status-response validation.

Existing compensating controls help but do not close the defect: fail-closed verification, product/account/lineage binding, provider-authoritative reconciliation, a 128 KiB notification body ceiling, a 64 KiB authenticated-sync ceiling, and an authenticated sync rate limit. CapitolWonk's 60-second wrapper covers App Store Server API calls such as `setAppAccountToken` and `getAllSubscriptionStatuses`; it does **not** wrap `verifyAndDecode*` or the OCSP fetch. The public Notifications V2 verifier currently has no application-level OCSP deadline, response-size ceiling, or evidenced concurrency/abuse bound.

## Mandatory Acceptance Conditions

All applicable conditions must pass on the exact replacement candidate before Batch B or activation:

- **Correctness provenance:** for an official package, record version, integrity, upstream commit/tag, and proof that the npm tarball contains the accepted #447 fix. For a backport, record base/upstream commit, reviewer, exact patch hash, reproducible patch/lock output, and independent review result.
- **OCSP time policy:** require valid `thisUpdate`. Valid `YYYYMMDDHHMMSSZ` passes in UTC and non-UTC process time zones; test exact `-61`, `-60`, `+60`, and `+61` second skew boundaries. Future `thisUpdate`, expired `nextUpdate`, malformed/impossible dates, and a present `nextUpdate` earlier than `thisUpdate` fail closed. Because [RFC 6960 section 4.2.2.1](https://www.rfc-editor.org/rfc/rfc6960#section-4.2.2.1) permits missing `nextUpdate`, either reject it or enforce an explicitly approved maximum age no greater than 24 hours from `thisUpdate`.
- **Signed negative cases:** cryptographically signed fixtures cover `good`, `revoked`, and `unknown`; invalid response signature; mismatched CertID/serial/issuer hashes; unauthorized responder or wrong EKU; expired responder certificate; and no matching `SingleResponse`. Exercise full `verifyAndDecodeNotification` and transaction paths, not only a date helper. Every failure produces no entitlement write.
- **Adjacent Apple gaps:** online checks remain enabled. Issue #455 is fixed or a tested control actually aborts the request/socket and returns a retryable failure. Malformed/missing nested subscription-status data fails closed, covering issue #450.
- **Proposed measurable safety ceilings:** approve exact numbers before implementation. The starting proposal is to retain the 128 KiB notification body limit; cap each OCSP response at 256 KiB; abort each OCSP connection/read at 10 seconds; cap end-to-end verification at 15 seconds on the Vercel 1-vCPU/2-GB runtime; and limit each instance to four active verifier operations with no in-memory queue, returning retryable `503` for excess work. Parser-only 128 KiB stress fixtures should finish/fail within two seconds and add no more than 128 MiB RSS. An official library may choose a different real abort (open PR #456 proposes 30 seconds and no response-size cap); accepting different ceilings requires recorded platform/load evidence and explicit approval, and missing controls require a separately authorized local wrapper/fork.
- **Dependency and advisory gate:** a frozen Node `22.22.3` / pnpm `9.15.9` install has either zero `jsrsasign` paths after replacement or one exact approved Apple path with the recorded integrity. Any-severity advisory that affects a reachable X.509/ASN.1/OCSP function requires explicit triage; no untriaged high/critical production finding is allowed.
- **Residual EOL gate:** if the corrected path still includes `jsrsasign`, Tyler records a separate time-bounded acceptance, monitoring owner, expiry no later than November 30, 2026, and mandatory replacement triggers. A #447 correctness fix does not satisfy this gate.
- **Pre-Batch-B candidate evidence:** tampered/malformed/oversized fixtures, billing/release-source suite, TypeScript, lint, build, exact-head CI, matching Preview, and the default-off verifier/notification gate all pass. Apple sandbox/device delivery is not a pre-B requirement because production deployment remains default-off.
- **Pre-activation runtime evidence:** after fixed source is available, Apple sandbox, Notifications V2, signed-device, and Team lifecycle evidence pass on the exact SHA. Notifications V2 must use a separately approved callback-only public staging deployment/project on that SHA, backed only by non-production data and enforcing the approved size/timeout/concurrency controls. If this surface does not exist, runtime evidence remains open; do not disable protection for the existing whole Preview or enable the production callback as a shortcut.
- **Operational recovery:** implement and test a default-off verifier/notification activation gate **and** document an exact prior-SHA fail-closed rollback that can stop affected verification without granting entitlements. Record who may invoke either control, subscription-access behavior during the hold, and preauthorization/escalation rules.
- **Ownership:** Tyler records the selected path and residual decision; a named human monitoring/incident owner accepts the cadence and response SLA before Batch B.
