## Blocker B — `PUBLIC` database `CONNECT` and `TEMPORARY`

The preflight proves that both database-level privileges are present for `PUBLIC`; it does not name existing principals or prove which application, migration, scheduled, or managed connection currently relies on those grants. PostgreSQL treats `PUBLIC` as all current and future roles, and a role's effective privileges can also include direct grants and memberships. Removing `PUBLIC` `CONNECT` can therefore break **new** connections for a role that has no alternate path; existing sessions are not a sufficient smoke test. `TEMPORARY` may be used by a migration or operational path even if the normal application code does not mention temporary tables. See the [PostgreSQL 17 privilege](https://www.postgresql.org/docs/17/ddl-priv.html) and [REVOKE](https://www.postgresql.org/docs/17/sql-revoke.html) documentation.
